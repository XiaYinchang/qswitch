# 账号管理与多环境 Web

qswitch 按“实例 → 工具 → 已核实身份的账号 → 额度窗口 / 会话状态”组织管理。每台机器对自己的客户端和账号负责；Deck 在 `/qswitch/` 提供一次登录和页面内环境 Tab，业务操作转到所选实例。

## 能力与边界

| 类型 | 登录与身份 | 查询与续期 | 切换范围与限制 |
|---|---|---|---|
| Codex | 隔离 Device Code；账号 / workspace 身份 | 官方额度、闲置 OAuth 续期 | CLI 凭据；未核实身份的桌面快照不恢复；桌面运行时不能声称生成空闲 |
| Grok CLI | 隔离 Device Code；指定账号槽必须命中 | 当前共享账期，预付费 / 按量余额保留；官方 OAuth 锁 | CLI 凭据；不改 Grok Bot；多槽身份不明确时拒绝 |
| Cursor | 官方客户端登录后收录；macOS 核对 IDE / CLI 一致性，Linux / Windows 核对 CLI 身份 | Auto / API 额度与额外余额；当前未实现安全续期 | macOS 同时写 IDE 和 CLI，须先退出桌面端；Linux / Windows 仅管理 CLI，不读写桌面数据库 |
| Grok Bot | Cursor 账号关联的只读额度 | 独立观测时间与失败状态 | 不提供独立切号，不把浏览器快照绑定到 Grok CLI |
| Devin CLI | 在线验证 API key 所属身份 | 按套餐识别日 / 周窗口，Max 只看周额度 | CLI 配置；Devin App 独立，不随 CLI 关闭或换号 |
| Kimi Code | 官方登录后 `/me` 核验 | 官方额度；同身份桌面月额度只读补充；macOS/Linux 一次性 OAuth 续期可恢复，Windows 由原生客户端续期 | 所有 Kimi CLI 退出后更新凭据；不自动发送续接 |
| Claude Code | Linux 隔离授权；官方 profile 核验 | 5h / 7d；一次性续期日志与恢复 | Linux/macOS 文件凭据；macOS Keychain 不支持；受管会话空闲协调，保留现有提前轮换政策；Windows 不支持受管切换 |
| ZCode | 读取桌面 Coding Plan | 5h / 周模型额度，月 MCP 单独展示 | 只读监控，不替客户端登录或切号 |
| Antigravity | 原生 App / agy 登录；系统凭据及原生身份核验 | Gemini、第三方各 5h / 周，支持 macOS / Linux / Windows | 两组均确认耗尽才自动切；原生会话空闲后统一更新 App / CLI，核验失败回滚 |

各平台的动作由后端 capability 决定，不靠前端按工具名称猜测。没有可靠接口的能力明确显示原因；不会为了表面一致而启用无法验证的桌面操作。新增账号登录由使用者完成。

Linux / Windows 使用旧 Cursor 账号时，若它仅因缺少桌面凭据被标成不完整，会在工具锁内重新核验保存的 CLI 身份与 token。验证通过只修正该标记，不清除认证退避、过期标记或额度；无法核实的快照仍要求重新收录，不从桌面凭据补造 CLI 登录。

## 状态和额度

认证有效性、额度、会话忙闲、自动切换设置和实例范围分别展示。未安装、未登录、未知、接口失败、历史观测和明确耗尽不能互相替代。关闭自动切换只停止切号，继续收录、查询和安全续期；全局关闭时，单工具开关不会冒充已经生效。即使当前平台不支持自动切换，也可以停用此前保存的启用配置。

耗尽使用供应商原始字段和真实上限，不把 99.5% 当成 100%。缺失必要窗口时保持未知；协议明确规定的省略零值仍按该协议处理。Grok Bot 查询失败不能继承 Cursor 查询成功的时间，单账号和批量查询反馈也独立判断是否确认了 Bot 额度。

升级后首次打开旧状态库时，Codex、Cursor、Devin、Kimi 的旧成功额度记录统一撤销切换授权，等待新规则重新查询。历史百分比、窗口与日志仍保留，原有认证和 HTTP 失败退避不变；新结果不会在后续启动时反复清除。Antigravity、Claude、Grok 的既有证据规则不受这次迁移影响。

Antigravity 按以下条件执行：

1. 每组任一完整有效窗口达到上限，该组受限。
2. Gemini 和第三方两组均受限，且结果完整、成功、未过期，才允许排队。
3. 缺失窗口、接口失败、重置时间不明确或任一组恢复时，撤销旧证据及待切任务。
4. 候选账号按最长窗口的重置时间先后选择；不使用 Claude 提前轮换规则。
5. 核对客户端身份，并在系统凭据读取与事务快照校验完成后、首次写入前再次核对原生凭据、自动开关与额度证据。用户已换号、凭据已更新、自动切换已关闭或额度依据已过期时，取消原排队，保留当前登录。

Claude 保留原有最长窗口 12 小时内、余量至少 10%、早于当前账号重置的提前轮换，以及受管会话后台等待上限和 cron 规则。普通非受管 Claude 不纳入切号协调。

## 可靠性

工具锁覆盖收录、续期、查询与切换。配置更新在跨进程锁内重读，只改指定字段。凭据写入失败或最后的状态提交失败时回滚受影响文件；缺失文件恢复为缺失，Cursor 只回滚认证键，不覆盖其他数据库内容。

Kimi 和 Claude 在消费一次性 refresh token 前先持久记录意图；新凭据先加密落盘，再写账号与当前登录。重启后可以恢复未完成写回；外部新登录和主动登出不覆盖。响应丢失时停止重用旧 token，重新登录可以替代不确定的凭据。对不透明 token，内容不同不代表账号不同；必须核对当前在线身份再消费闲置凭据。

完成续期后，先同步账号凭据所在目录，再删除恢复记录。目录打开或同步失败时保留加密恢复结果，后续启动仍可继续写回。

这些保证覆盖已有操作的明确失败和 OAuth 续期中断；不承诺任何供应商、任意客户端版本上的完整事务或未公开接口稳定性。

## Web 操作

桌面按工具、账号列表、账号详情组织，手机按屏宽折叠。常用动作集中在所属工具和账号，自动开关放在工具管理区。删除放入次级操作；额度四个窗口、错误原因、观测时间及恢复状态可直接查看。

导航只显示当前机器已有账号的工具；隐藏空类型不改变后台管理范围。新增类型通过统一的“添加账号”入口，登录或收录成功后自动出现在导航中。删除最后一个账号后，该类型隐藏并切到仍有账号的工具；全部为空时显示添加入口。

“刷新页面”只读本机状态，“查询额度”才请求供应商。后台只读刷新在页面可见时运行，不反复重建整个页面；保留焦点、选择和展开状态。同工具写操作互斥，旧响应不能覆盖新结果。写请求超时显示结果待核验，不自动重放；供应商查询失败不会被后续刷新掩盖。

首次加载由入口目录同时返回登录状态，再读取所选实例的总览；总览中的实例 ID 核验成功后才允许操作，无须先发健康检查。切换节点只读取一次总览；同一环境、同一操作版本的在途读取共用结果，操作完成后重新读取，重复点击当前已连接的环境不清空页面。只读取所选节点，不预先扫描其他节点或用旧快照代替当前连接状态。

每次总览只探测一遍各工具的会话状态，Claude 的受管会话详情与阻塞进程来自同次观测。探测失败显示“会话状态未知”；实际切号和续期仍独立执行实时检查。

切换环境立即清空原账号内容并关闭确认、登录面板；加载失败或实例不符时禁止写入。请求、授权轮询及取消都绑定发起时的环境，旧响应不能修改新环境的状态。在途写操作按环境与工具去重，切走再返回也不重复提交。环境与工具选择保存在地址中，刷新及前进后退使用同一校验流程。

Device Code 登录提供复制、有效期、重试、取消和焦点恢复；轮询串行，取消后不继续更新旧会话。页面、登录页和对话框使用同一套视觉、键盘和无障碍语义。

## 实例、权限与发布

实例 ID 自动持久生成，显示名可配置，版本和 worker 范围来自当前 daemon。环境目录只存名称和实例 ID，由部署维护；页面只展示目录，不接受任意代理地址。统一登录、退出、会话和目录属于入口；健康、总览、授权及账号操作属于所选实例。直接打开 loopback 页面只管理本机。

所有环境 API 请求要求与固定路由一致的实例标识，目标服务再核对自身 ID；浏览器还要求同源。nginx 的内部认证请求向 novix 校验统一 Cookie 或入口 Bearer，再用目标独立 token 请求对应实例，清除浏览器 Cookie。代理不覆盖目标实例头，也不重放 POST。目标 token 和供应商凭据均不发给页面；目标认证失败与统一登录失效分别处理。novix 认证服务不可用时所有远程操作停止，单台设备离线只影响该环境。

Book 仅管理 Antigravity 时，总览和操作也只有该工具，不显示其他工具已托管的假象。账号凭据不跨机复制；同账号多机观测不汇总为重复额度。原 `/qswitch-mini/`、`/qswitch-book/` 页面路径退役。

发布用一个标签和清单覆盖 novix、Mini、Book。构建在 devbox / CI，安装前校验制品、切号状态和当前版本，安装后核对实例 ID、版本、范围、总览与公开入口。失败回滚，成功删除临时文件与备份；登录供应商不作为安装完成条件。

macOS 服务加载失败时，先检查任务是否已注册；尚未注册才用非交互 sudo 进入所属用户的图形会话重试。部署与回滚使用同一启动路径；两种会话都失败时明确报告恢复未完成，不写成功记录。

平台能力由合成回归、原生 CI 和可达设备分别验证；真实账号登录与真实耗尽切号须与代码实现、部署和合成验收分开记录。
